# 蘑菇大棚 IoT 管理系统 — 鸿蒙开发技术应用说明

> 本文档详细说明 SoftwareAction 项目在 **HarmonyOS（鸿蒙）** 平台上实际使用的开发技术、系统能力与工程实践。
> 目标 API：**6.1.1(24)**；目标设备：phone / tablet / 2in1 / car / wearable / tv 六端。
> bundle：`com.example.softwareaction`
>
> **本文档重点突出鸿蒙特有技术**：Stage Model 应用模型、ArkTS 语言、ArkUI 声明式 UI、一次开发多端部署、系统能力 Kit、Hvigor 构建系统、OHPM 包管理、PersistentStorage 持久化、canIUse 能力查询等。

## 一、鸿蒙开发特性总览

HarmonyOS 是华为自研的分布式操作系统，其应用开发范式与 Android/iOS 有本质差异。本项目深度使用以下鸿蒙核心特性：

### 1.1 鸿蒙独有的开发范式

| 特性 | 鸿蒙实现 | 本项目应用 | 与传统开发的差异 |
|------|----------|------------|------------------|
| **应用模型** | Stage Model（UIAbility + AbilityStage） | EntryAbility 继承 UIAbility | 替代 Android Activity / iOS UIViewController，基于 Stage 模型组织生命周期 |
| **开发语言** | ArkTS（TypeScript 超集 + 鸿蒙类型系统） | 全项目使用 .ets 文件 | 在 TS 基础上增加 @Component/@State 等装饰器，禁用 any/dynamic，强制类型安全 |
| **UI 范式** | ArkUI 声明式 UI | 全部页面用 @Component struct | 类似 Flutter/SwiftUI，但装饰器系统是鸿蒙原生 |
| **多端部署** | 一次开发多端部署（五断点 + GridRow/GridCol） | 五断点 XS~XL 全覆盖 | 鸿蒙核心理念，单代码库覆盖手表到 PC |
| **能力查询** | canIUse() 系统能力检测 | MapKit/Crypto 等调用前守卫 | 鸿蒙分布式架构下设备能力异构，必须运行时查询 |
| **状态管理** | AppStorage + PersistentStorage + 装饰器 | 全局状态共享 | 鸿蒙特有全局状态机制，替代 Redux/MobX |
| **路由系统** | Navigation + NavPathStack + NavDestination | 全部页面路由 | 鸿蒙特有路由组件，支持跨模块 |
| **构建系统** | Hvigor + hvigorw | 全项目构建 | 替代 Gradle，鸿蒙原生构建工具 |
| **包管理** | OHPM + oh-package.json5 | 三模块依赖管理 | 替代 npm，鸿蒙专用包管理 |
| **模块化** | HAR（共享包）/ HAP（应用包）/ HSP（动态共享包） | 三层架构用 HAR/HAP | 鸿蒙特有模块类型，区别于 Android AAR |

ArkUI 装饰器是鸿蒙声明式 UI 的核心，本项目实际使用的装饰器：

## 三、工程架构与模块化

> **鸿蒙特性**：HAR/HAP/HSP 三种模块类型是鸿蒙特有概念，区别于 Android 的 AAR/APK。Hvigor 构建系统与 OHPM 包管理是鸿蒙原生工具链，替代 Gradle/npm。

### 3.1 三层架构

项目遵循严格的单向依赖三层架构，使用 **Hvigor 多模块机制**：

```
common/base (HAR)  →  features/core (HAR)  →  entry (HAP)
   公共能力              业务逻辑                产品入口
```

| 层级 | 模块 | 包名 | 关键目录 | hvigor 任务 |
|------|------|------|----------|-------------|
| 公共 | common/base | `common-base` | `constants/`、`utils/`、`components/` | `harTasks` |
| 业务 | features/core | `features-core` | `pages/`、`viewmodel/`、`model/`、`service/`、`theme/` | `harTasks` |
| 产品 | entry | — | `entryability/`、`pages/`、`src/test/` | `hapTasks` |

**鸿蒙模块类型差异**：
- **HAR（Harmony Archive）**：鸿蒙共享包，类似 Android AAR，可被多个 HAP 引用。使用 `harTasks` 构建。
- **HAP（Harmony Ability Package）**：鸿蒙应用包，类似 Android APK，是应用安装单元。使用 `hapTasks` 构建。
- **HSP（Harmony Shared Package）**：鸿蒙动态共享包，运行时动态加载（本项目未用）。

**依赖方向（严格单向）**：

- `entry → features-core → common-base` ✅
- `common-base → features-core` ❌（禁止反向）
- `features-core → entry` ❌（禁止反向）
- 模块间横向调用 ❌（禁止）

### 3.2 OHPM 包管理配置

鸿蒙使用 **OHPM（Open Harmony Package Manager）** 替代 npm，各模块通过 `oh-package.json5` 声明依赖，包名导入而非相对路径：

- 根 `oh-package.json5`：`common-base: file:./common/base`、`features-core: file:./features/core`、devDependencies `@ohos/hypium: 1.0.25`、`@ohos/hamock: 1.0.0`
- `features-core`：`main: ./Index.ets`，依赖 `common-base: file:../../common/base`
- `common-base`：`main: ./Index.ets`，无依赖（最底层）

**barrel 导出**（鸿蒙模块化最佳实践）：`features-core/Index.ets` 与 `common-base/Index.ets` 作为模块对外门面，统一 `export` 所有公共类、接口与组件，消费方使用 `import { XxxPage, ThemeManager } from 'features-core'` 形式导入。

### 3.3 模块类型区分（hvigorfile）

HAR 与 HAP 通过 hvigorfile 区分，这是鸿蒙特有配置：

```typescript
// entry/hvigorfile.ts（HAP - 应用包）
import { hapTasks } from '@ohos/hvigor-ohos-plugin';
export default { system: hapTasks, plugins: [] };

// common/base/hvigorfile.ts、features/core/hvigorfile.ts（HAR - 共享包）
import { harTasks } from '@ohos/hvigor-ohos-plugin';
export default { system: harTasks, plugins: [] };
```

## 四、Stage Model 与应用生命周期

> **鸿蒙特性**：Stage Model 是鸿蒙 3.1+ 引入的应用模型，替代早期的 FA（Feature Ability）模型。核心概念 UIAbility、AbilityStage、WindowStage、Want 均为鸿蒙独有。与传统 Activity 模型相比，Stage Model 强调「UI 与业务分离」「窗口化」「基于 Want 的显式调用」。

### 4.1 EntryAbility 实现

应用入口为 [EntryAbility.ets](file:///d:/SoftwareAction/entry/src/main/ets/entryability/EntryAbility.ets)，继承 `UIAbility`（鸿蒙 Stage Model 的核心能力载体），基于 Stage Model 的生命周期回调组织初始化流程。

**鸿蒙 Kit 导入**（注意 `@kit.*` 命名空间是鸿蒙特有）：

```typescript
import { AbilityConstant, ConfigurationConstant, UIAbility, Want } from '@kit.AbilityKit';
import { hilog } from '@kit.PerformanceAnalysisKit';
import { window } from '@kit.ArkUI';
import { IotService, ThemeManager } from 'features-core';
import { IOT_CONFIG } from './IotConfig';
```

| 鸿蒙概念 | 说明 |
|----------|------|
| `UIAbility` | Stage Model 核心，承载 UI 生命周期，类似 Android Activity 但更轻量 |
| `Want` | 鸿蒙特有的显式调用机制，类似 Android Intent，用于跨 Ability 通信 |
| `AbilityConstant` | 启动参数常量（LaunchParam 含启动原因） |
| `ConfigurationConstant` | 配置常量（ColorMode 等） |
| `window.WindowStage` | 鸿蒙窗口舞台，管理 UI 内容加载 |

**onCreate 三步初始化**（全部 try-catch 包裹，保证单点失败不影响整体启动）：

```typescript
async onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): Promise<void> {
  // 1. 锁定浅色模式：鸿蒙 ConfigurationConstant.ColorMode 系统能力
  //    双主题均在浅色底色上设计，跟随系统深色会导致淡彩 token 被系统反转 → 发黄
  this.context.getApplicationContext()
    .setColorMode(ConfigurationConstant.ColorMode.COLOR_MODE_LIGHT);

  // 2. 初始化 IoT 服务（应用侧 API），全局单例，所有 ViewModel 共用
  IotService.getInstance().init(IOT_CONFIG);

  // 3. 主题初始化（PersistentStorage 已在构造时自动从磁盘恢复 → AppStorage）
  //    PersistentStorage 是鸿蒙特有持久化机制，自动同步 AppStorage 与磁盘
  ThemeManager.getInstance().init();
}
```

**onWindowStageCreate 加载入口页**（鸿蒙特有窗口加载机制）：

```typescript
onWindowStageCreate(windowStage: window.WindowStage): void {
  // windowStage.loadContent 是鸿蒙 Stage Model 加载 UI 内容的 API
  windowStage.loadContent('pages/Index', (err) => {
    if (err.code) { hilog.error(DOMAIN, 'testTag', '...'); return; }
    hilog.info(DOMAIN, 'testTag', 'Succeeded in loading the content.');
  });
}
```

其余回调（`onDestroy`、`onWindowStageDestroy`、`onForeground`、`onBackground`）以 hilog 日志为主。

### 4.2 hilog 日志规范

使用 `@kit.PerformanceAnalysisKit` 的 `hilog`（鸿蒙统一日志系统），DOMAIN 统一 `0x0000`，标签 `'testTag'`，格式串 `'%{public}s'` 显式标记公开输出（鸿蒙日志的隐私控制机制，`%{private}s` 会脱敏）。错误对象通过 `JSON.stringify(err)` 序列化。common-base 层封装了 `Logger` 工具类作为统一日志门面。

### 4.3 main_pages.json 路由注册

[main_pages.json](file:///d:/SoftwareAction/entry/src/main/resources/base/profile/main_pages.json) 是鸿蒙特有路由注册表，**只注册 Index 一个页面**：

```json
{ "src": ["pages/Index"] }
```

所有子页面（AlertPage、GrowthPage、RecipePage、VideoMonitorPage 等）从 features-core 模块 import，通过 `@Builder PageDestination(name)` 工厂渲染（鸿蒙 NavDestination 机制），无需在路由表注册。

## 五、ArkUI 响应式布局与多端部署

> **鸿蒙特性**：「一次开发多端部署」是鸿蒙核心理念，通过五档断点（XS/SM/MD/LG/XL）+ GridRow/GridCol 响应式组件 + canIUse 能力检测实现单代码库覆盖全设备形态。这是鸿蒙区别于 Android（需 phone/tablet/wear 多套代码）的核心优势。

### 5.1 五档断点系统（鸿蒙多端部署核心）

[BreakpointConstants.ets](file:///d:/SoftwareAction/common/base/src/main/ets/constants/BreakpointConstants.ets) 定义五档断点，覆盖从手表到大屏的全部设备形态：

| 断点 | 常量 | 阈值(vp) | 设备映射 |
|------|------|----------|----------|
| XS | `BreakpointConstants.XS` (`'xs'`) | 0–320 | 手表 |
| SM | `BreakpointConstants.SM` (`'sm'`) | 320–600 | 手机竖屏 |
| MD | `BreakpointConstants.MD` (`'md'`) | 600–840 | 折叠屏 / 小平板 |
| LG | `BreakpointConstants.LG` (`'lg'`) | 840–1440 | 平板横屏 |
| XL | `BreakpointConstants.XL` (`'xl'`) | 1440+ | 大屏 / PC |

**鸿蒙断点机制**：鸿蒙系统本身提供 `BreakpointSystem` 能力，但本项目采用手动 `onAreaChange` 监听方式实现，更精细控制断点切换逻辑。

### 5.2 断点检测与全局共享

[Index.ets](file:///d:/SoftwareAction/entry/src/main/ets/pages/Index.ets) 在 `build()` 根容器挂载 `onAreaChange`（鸿蒙特有的事件回调），读取 `newArea.width` 并通过 if/else 链比对四个阈值，计算当前断点：

```typescript
.onAreaChange((_old, newArea) => {
  const w = newArea.width;
  let bp: string;
  if (w >= BREAKPOINT_XL) bp = 'xl';
  else if (w >= BREAKPOINT_LG) bp = 'lg';
  else if (w >= BREAKPOINT_MD) bp = 'md';
  else if (w >= BREAKPOINT_SM) bp = 'sm';
  else bp = 'xs';
  this.currentBreakpoint = bp;
  AppStorage.setOrCreate<string>('currentBreakpoint', bp);  // 鸿蒙全局状态
})
```

断点写入 `AppStorage`（鸿蒙特有全局状态存储），七个业务页面通过 `@StorageLink('currentBreakpoint') currentBreakpoint: string = BreakpointConstants.SM` 实时响应尺寸变化。**这是鸿蒙跨组件状态同步的特有机制，无需 Redux/MobX 等第三方状态库**。

### 5.3 AdaptiveUtils 自适应工具

同文件内 `AdaptiveUtils` 类提供按断点返回布局参数的静态方法，集中管理多端差异：

| 方法 | XS | SM | MD | LG | XL | 用途 |
|------|----|----|----|----|----|------|
| `getSensorColumns` | 2 | 2 | 3 | 4 | 6 | 传感器网格列数 |
| `getDeviceColumns` | 1 | 1 | 2 | 3 | 4 | 设备卡片列数 |
| `getCardColumns` | 1 | 1 | 2 | 2 | 3 | 通用卡片列数 |
| `getPagePadding` | 8 | 12 | 16 | 24 | 32 | 页面左右内边距 |
| `getCardGap` | 6 | 10 | 12 | 16 | 20 | 卡片间距 |
| `getSensorDataFontSize` | 20 | 24 | 28 | 32 | 40 | 传感器数值字号 |
| `getTitleFontSize` | 16 | 18 | 20 | 24 | 28 | 标题字号 |

**布局判定方法**：

- `isDualPane(bp)`：MD/LG/XL 返回 true → 触发侧栏布局
- `isLargeScreen(bp)`：LG/XL 返回 true

**侧栏宽度**：`getSideBarWidth()` 返回固定 220vp，容纳「矢量图标 + 文字」横排，符合平板/2in1 标准比例。

**内容限宽**：`getMaxContentWidth(bp)` 返回各断点内容区最大宽度，**已扣除侧栏占用**，让内容在「屏幕−侧栏」的内容区内居中留白：

- MD：720 − 220 = 500vp
- LG：1100 − 220 = 880vp
- XL：1280 − 220 = 1060vp
- XS/SM：返回 0（不限宽，全宽填充）

### 5.4 双模式入口布局（鸿蒙 Navigation + Tabs）

[Index.ets](file:///d:/SoftwareAction/entry/src/main/ets/pages/Index.ets) 的 `build()` 根据断点切换两种布局模式，使用鸿蒙 `Navigation` 与 `Tabs` 组件：

```typescript
build() {
  Row() {
    if (this.isSideBarLayout()) {
      this.SideNavBar()          // 宽屏：左侧 220vp 侧栏
    }
    Column() {
      if (this.isSideBarLayout()) {
        this.TabContentArea()    // 宽屏：Navigation + 当前页
      } else {
        this.TabsBottom()        // 窄屏：底部 Tabs
      }
    }.layoutWeight(1)
  }
}
```

| 模式 | 适用断点 | 布局 |
|------|----------|------|
| **窄屏** | XS、SM | `Tabs(barPosition=End)` 底部 TabBar，四个 TabContent 内联页面 |
| **宽屏** | MD、LG、XL | `SideNavBar`(220vp) + `Navigation(mode=Stack)` 内容区 |

### 5.5 GridRow / GridCol 响应式网格（鸿蒙特有组件）

`GridRow` / `GridCol` 是鸿蒙特有的响应式布局组件，基于 12 列栅格系统，按断点动态分配 span。六个业务页面（DashboardPage、DevicePage、ProfilePage、RecipePage、AlertPage、MapPage）使用 `GridRow` + `GridCol` 实现列数自适应。典型示例（[DashboardPage.ets](file:///d:/SoftwareAction/features/core/src/main/ets/pages/DashboardPage.ets)）：

```typescript
GridRow({ gutter: { x: 10, y: 10 } }) {
  ForEach(this.sensors, (item: SensorDataItem, index: number) => {
    GridCol({ span: this.getSensorSpan() }) {
      this.SensorCard(item, index)
    }
  })
}
```

`getSensorSpan()` 按断点动态计算 span：`Math.floor(12 / AdaptiveUtils.getSensorColumns(currentBreakpoint))`，总 12 列反推每卡片占用列数（XS/SM=6 即 2 列，MD=4 即 3 列，LG=3 即 4 列，XL=2 即 6 列）。

### 5.6 设备能力检测（鸿蒙分布式架构核心）

**`canIUse()` 是鸿蒙特有的系统能力查询 API**，用于分布式架构下设备能力异构场景。鸿蒙设备形态多样（手表无地图、TV 无触屏），必须运行时查询能力。

[CapabilityUtils.ets](file:///d:/SoftwareAction/common/base/src/main/ets/utils/CapabilityUtils.ets) 封装 `canIUse()` 安全调用，捕获异常返回 false：

```typescript
static canIUseSafe(api: string): boolean {
  try { return canIUse(api); } catch { return false; }
}
```

设备类型枚举 `DeviceCategory`：phone / tablet / 2in1 / car / wearable / tv / unknown，提供 `supportsMap()`、`supportsChart()`、`supportsComplexLayout(bp)`、`supportsKeyboard(bp)`、`supportsVoice()`、`maxListItems()` 等能力判定方法。

**典型应用场景**：
- 调用 `@kit.MapKit` 前查询 `SystemCapability.Map.Core`
- 调用 `@kit.CryptoArchitectureKit` 前查询加密能力
- TV 设备无触屏，需切换焦点导航
- 手表设备能力受限，启用极简布局

### 5.7 矢量图标自绘（ArkUI 几何组件）

[Index.ets](file:///d:/SoftwareAction/entry/src/main/ets/pages/Index.ets) 的 `NavIcon(type, color)` 用纯 ArkUI 几何组件（`Path`/`Circle`/`Rect`/`Column`）绘制 4 个导航图标（home/device/map/profile），基准 20×20vp，`color` 参数着色实现主题感知，与 [MapPage.MapIcon](file:///d:/SoftwareAction/features/core/src/main/ets/pages/MapPage.ets) 风格统一，替代 emoji 保证多端渲染一致（鸿蒙多端字体差异会导致 emoji 渲染不一致）。

## 六、导航与路由系统

> **鸿蒙特性**：`Navigation` + `NavPathStack` + `NavDestination` 是鸿蒙特有路由三件套，替代 React Navigation 等第三方方案。支持跨模块路由、双栏自适应（Stack/Split 模式）、`AppStorage` 共享路由栈。

### 6.1 AppRouter 单例

[AppRouter.ets](file:///d:/SoftwareAction/entry/src/main/ets/pages/AppRouter.ets) 以单例持有全局 `NavPathStack`（鸿蒙特有路由栈），解决 `@Component V1` 页面不能直接接收 NavPathStack 参数的问题：

```typescript
export class AppRouter {
  private static instance: NavPathStack;
  static getStack(): NavPathStack {
    if (!AppRouter.instance) AppRouter.instance = new NavPathStack();
    return AppRouter.instance;
  }
  static push(name: string): void { this.getStack().pushPath({ name }); }
  static pop(): void { this.getStack().pop(); }
  static pushWithParam(name: string, param: object): void {
    this.getStack().pushPath({ name, param });
  }
}
```

### 6.2 NavPathStack 全局共享

[Index.ets](file:///d:/SoftwareAction/entry/src/main/ets/pages/Index.ets) 在 `aboutToAppear` 将栈写入 `AppStorage`（鸿蒙跨模块状态共享），供 features-core 页面跨模块调用：

```typescript
@State navPathStack: NavPathStack = AppRouter.getStack();

aboutToAppear(): void {
  AppStorage.setOrCreate<NavPathStack>('navPathStack', this.navPathStack);
}
```

业务页面通过 `@StorageLink('navPathStack')` 或 `AppStorage.get` 取栈后 `pushPath`，如 DashboardPage 跳转告警页、MapPage 跳转大棚详情。**这种跨模块路由共享是鸿蒙特有机制，依赖 AppStorage 全局状态**。

### 6.3 PageDestination Builder 工厂

[Index.ets](file:///d:/SoftwareAction/entry/src/main/ets/pages/Index.ets) 用 `@Builder PageDestination(name: string)` 作为 `NavDestination` 工厂。**因 ArkTS 不支持动态属性访问**（鸿蒙类型系统限制），用 if/else 分支映射路由名到页面组件：

```typescript
@Builder
PageDestination(name: string) {
  if (name === 'AlertPage') {
    NavDestination() { AlertPage() }.hideTitleBar(true)
  } else if (name === 'GrowthPage') {
    NavDestination() { GrowthPage() }.hideTitleBar(true)
  } else if (name === 'RecipePage') {
    NavDestination() { RecipePage() }.hideTitleBar(true)
  } else if (name === 'VideoMonitorPage') {
    NavDestination() { VideoMonitorPage() }.hideTitleBar(true)
  } else if (name === 'DashboardPage') {
    NavDestination() { DashboardPage() }.hideTitleBar(true)
  }
}
```

绑定到 Navigation：`.navDestination(this.PageDestination)`。

### 6.4 Navigation 模式（鸿蒙特有路由模式）

鸿蒙 `Navigation` 组件支持三种模式：`Stack`（推入式）、`Split`（分栏）、`Auto`（自动）。窄屏 `TabsBottom` 与宽屏 `TabContentArea` 均使用 `Navigation(mode=Stack)` 包裹内容，共享同一 `navPathStack`，保证跨模式 push/pop 行为一致：

```typescript
Navigation(this.navPathStack) {
  Column() { /* 当前页 */ }.width('100%').height('100%')
}
.mode(NavigationMode.Stack)   // 鸿蒙特有路由模式
.hideTitleBar(true)
.navDestination(this.PageDestination)
```

> **经验教训**：曾使用 `NavigationMode.Auto`（自动选择 Stack/Split），但在 MatePad 13 等宽屏设备上自动切换到 Split 模式导致内容被压缩到左栏显示半页。最终改为 `NavigationMode.Stack` 强制推入式，保证全宽显示。

## 七、状态管理

> **鸿蒙特性**：ArkUI 装饰器系统（@State/@Prop/@Link/@Watch/@StorageLink 等）是鸿蒙特有状态管理机制，无需 Redux/MobX。`AppStorage` 是鸿蒙全局状态存储，`PersistentStorage` 是鸿蒙磁盘持久化机制，二者配合实现跨页状态同步与持久化。

### 7.1 装饰器使用策略（ArkUI 装饰器决策树）

项目按状态作用域选择装饰器（鸿蒙装饰器决策树），实际使用情况：

| 装饰器 | 使用规模 | 场景 | 鸿蒙语义 |
|--------|----------|------|----------|
| `@State` | 109 处 / 13 文件 | 页面局部状态 | 组件内可变，触发重渲染 |
| `@Prop` / `@Link` | 同上 | 父子组件传值 | `@Prop` 单向，`@Link` 双向 |
| `@Watch` | 配合 `@StorageLink` | 主题切换响应 | 状态变化回调 |
| `@StorageLink` | 22 处 / 10 文件 | 跨页全局状态 | 双向绑定 AppStorage |
| `@Provide` / `@Consume` | 未使用 | — | 跨层级双向同步（用 AppStorage 替代） |
| `@Observed` / `@ObjectLink` | 未使用 | — | 嵌套对象响应式（用状态拆分替代） |

跨页状态完全依赖 `AppStorage` + `@StorageLink`，未采用 `@Provide/@Consume` 与 `@Observed/@ObjectLink`。

### 7.2 AppStorage 键值清单（鸿蒙全局状态）

| 键 | 写入位置 | 消费位置 | 用途 |
|----|----------|----------|------|
| `navPathStack` | Index.ets aboutToAppear | DashboardPage、ProfilePage、MapPage、VideoMonitorPage | 共享路由栈 |
| `currentBreakpoint` | Index.ets onAreaChange | 七个业务页面 `@StorageLink` | 响应式断点 |
| `themeName` | ProfilePage 切换时 | 全部页面 `@StorageLink` | 主题名双向绑定 |
| `deviceType` | CapabilityUtils | CapabilityUtils | 设备类型缓存 |
| `videoMonitorGreenhouseId` | MapPage | VideoMonitorPage | 跨页传参（大棚 ID） |

### 7.3 状态拆分原则（ArkUI 性能优化）

页面将状态按「刷新频率 + 关联 UI」拆分为多个独立 `@State`，避免大对象整体重建。**这是鸿蒙 ArkUI 性能优化的关键实践**——每个 `@State` 变化只触发关联 UI 重渲染。以 [DashboardPage.ets](file:///d:/SoftwareAction/features/core/src/main/ets/pages/DashboardPage.ets) 为例：

```typescript
@State sensors: SensorDataItem[] = [];      // 传感器列表
@State controls: ControlItem[] = [];        // 控制项
@State overviewOnline: number = 0;          // 概览统计
@State trendData: ChartPoint[] = [];        // 24h 趋势
@State pulseScale: number = 1;              // 脉冲动画
@State cardEntrance: number = 0;            // 卡片入场动画
@State breathingPhase: number = 0;          // 呼吸光晕动画
```

### 7.4 主题切换响应（@Watch 联动）

页面通过 `@StorageLink('themeName') @Watch('onThemeChange')` 双装饰器响应主题切换：

```typescript
@StorageLink('themeName') @Watch('onThemeChange') themeName: string = 'frosted';

onThemeChange(): void {
  this.applyEntranceForCurrentTheme();
}
```

### 7.5 条件渲染规避 @StorageLink 失效

**鸿蒙 Tabs 组件特性**：Tabs 会保留所有 TabContent 实例，非活跃页面的 `@StorageLink('themeName')` 可能不触发 build()。解决方案：每个 TabContent 内用 `if (this.currentIndex === N)` 条件渲染，确保切页时旧页面销毁、新页面重建并读取最新主题。

## 八、主题系统

> **鸿蒙特性**：`PersistentStorage` 是鸿蒙特有的「AppStorage ↔ 磁盘」自动同步机制，无需手动读写文件。配合 `@StorageLink` 实现主题名全局双向绑定 + 自动持久化，是鸿蒙状态管理的典型应用。

### 8.1 架构设计

主题系统采用 **PersistentStorage + AppStorage + ThemeManager 单例** 的原子替换架构（[ThemeManager.ets](file:///d:/SoftwareAction/features/core/src/main/ets/theme/ThemeManager.ets)）：

```
PersistentStorage.persistProp('themeName', 'frosted')   ← 鸿蒙特有持久化 API
  → AppStorage 全局唯一真相源 + 自动磁盘持久化
  → @StorageLink 双向绑定到所有页面
  → 组件写 this.themeName = newValue → 自动同步全部页面 + 磁盘
```

ThemeManager 只负责持有 theme token 映射 + `setTheme` 同步更新，不手动操作 preferences。

### 8.2 ThemeManager 单例

```typescript
export class ThemeManager {
  private static instance: ThemeManager;
  private current: ThemeTokens = FROSTED_THEME;

  private constructor() {
    // 鸿蒙特有：PersistentStorage.persistProp 一次持久化，自动同步 AppStorage 与磁盘
    PersistentStorage.persistProp('themeName', THEME_FROSTED);
  }
  static getInstance(): ThemeManager { /* 懒加载 */ }
  init(): void { /* 从 AppStorage 同步 current，EntryAbility 调一次 */ }
  getTokens(): ThemeTokens { return this.current; }
  isFrosted(): boolean { return this.current.name === THEME_FROSTED; }
  setTheme(themeName: string): void { /* 同步 current */ }
  toggle(): void { /* 两主题切换 */ }
}
```

**切换时序**（ProfilePage）：① `ThemeManager.setTheme()` 同步更新 current → ② 写 `this.themeName`（@StorageLink）→ 触发全部页面 rebuild → 各页面 `t()` 调用 `getTokens()` 取新主题。

### 8.3 ThemeTokens 接口

[ThemeTokens.ets](file:///d:/SoftwareAction/features/core/src/main/ets/theme/ThemeTokens.ets) 定义约 50 个只读属性，按分类组织：

| 分类 | 属性示例 | 数量 |
|------|----------|------|
| 品牌色 | `primary`、`primaryLight`、`accent` | 5 |
| 功能色 | `success`、`warning`、`danger`、`info` | 5 |
| 背景 | `bgPage`、`bgCard`、`bgCardLight`、`bgTabBar` | 5 |
| Header 渐变 | `headerGradientTop`、`headerGradientBottom` | 2 |
| 文字 | `textTitle`、`textBody`、`textSub`、`textWhite` | 6 |
| 传感器配色 | `colorTemp`、`colorHumidity`、`colorCo2` | 6 |
| 圆角 | `radiusSm/Md/Lg/Xl/Full` | 5 |
| 阴影 | card/hover/header/float 各属性 | 12 |
| 毛玻璃 | `blurAmount` | 1 |

## 九、华为云 IoT 集成

> **鸿蒙特性**：使用 `@kit.NetworkKit` 的 `http` 模块进行网络请求，鸿蒙要求每个 `http.createHttp()` 实例必须 `destroy()` 释放，这是鸿蒙资源管理的强制规范。`@kit.CryptoArchitectureKit` 提供鸿蒙特有加密能力。

### 9.1 IotService 单例

[IotService.ets](file:///d:/SoftwareAction/features/core/src/main/ets/service/IotService.ets) 是 IoT 业务核心，全局单例，所有 ViewModel 共用。

**鉴权流程** `authenticate()`：

1. 先查 `IotTokenManager.getToken()` 缓存
2. 未命中则 `IamAuthUtil.requestToken(config)` 申请
3. 缓存 `setToken(token, 23 * 3600)` — IAM token 默认 24h，保守按 23h 缓存

**设备影子查询** `queryDeviceShadow()`（华为云 IoTDA 特有概念）：

- URL：`https://{iotdaEndpoint}:443/v5/iot/{projectId}/devices/{deviceId}/shadow`
- 方法：`http.RequestMethod.GET`（鸿蒙 NetworkKit 枚举），Header：`Content-Type: application/json` + `X-Auth-Token: token`
- **关键**：每次 `http.createHttp()` → `request()` → `httpRequest.destroy()` 释放实例（**鸿蒙 NetworkKit 强制规范**，不释放会内存泄漏）
- 响应解析：`JSON.parse(response.result.toString()) as Record<string, Object>`，按 `shadow` 字段取 `DeviceShadowService[]`

**命令下发** `sendCommand()`：

- URL：`.../devices/{deviceId}/commands`（同步命令；async-commands 对 MQTT 设备返回 IOTDA.014114）
- 方法：`http.RequestMethod.POST`，`extraData: JSON.stringify(body)`
- 请求体用 `class CommandBody`（**ArkTS 不允许 object literal 作 `Record<string, Object>`**，必须用 class）

**控制方法**（均走 sendCommand）：

| 方法 | 服务 | 命令 | Paras class | Paras 字段 |
|------|------|------|-------------|-----------|
| `controlLight(on)` | smartRoom | `SetLamp` | `SetLampParas` | `LampStatus: 'ON'/'OFF'` |
| `controlFan(on)` | smartRoom | `SetVent` | `SetVentParas` | `VentStatus` |
| `controlCondi(on)` | smartRoom | `SetCond` | `SetCondParas` | `CondStatus` |
| `controlBuzzer(on)` | smartRoom | `SetBuzzer` | `SetBuzzerParas` | `BuzzerStatus` |
| `recognizeOncePlantAI()` | plantAI | `recognizeOnce` | `RecognizeOnceParas` | 空 |

命令名与嵌入式 `mqtt.c handle_cloud_command` 严格对齐。

### 9.2 IamAuthUtil（IAM 鉴权 - 鸿蒙 NetworkKit）

[IamAuthUtil.ets](file:///d:/SoftwareAction/features/core/src/main/ets/service/IamAuthUtil.ets) 实现华为云 IAM v3 token 请求：

- **import**：`import { http } from '@kit.NetworkKit'`（鸿蒙网络 Kit）
- **URL 动态构造**：`iam.{region}.myhuaweicloud.com` + `/v3/auth/tokens`
- **请求体**（嵌套结构，ArkTS 要求用 interface 声明）：
  ```typescript
  {
    auth: {
      identity: {
        methods: ['password'],
        password: { user: { name, password, domain: { name: domainName } } }
      },
      scope: { project: { name: region } }
    }
  }
  ```
- **成功判定**：`responseCode !== 201 && !== 200` 才算失败（IAM 标准 201，容忍 200）
- **token 提取**：从 `response.header['x-subject-token']` 读取（IAM 把 token 放 header 而非 body）
- **资源释放**：`finally { httpRequest.destroy() }` 保证异常时也释放（**鸿蒙 NetworkKit 强制要求**）

### 9.3 IotTokenManager（token 缓存）

[IotTokenManager.ets](file:///d:/SoftwareAction/features/core/src/main/ets/service/IotTokenManager.ets)：

### 10.1 NetworkKit HTTP 规范（鸿蒙强制资源释放）

**鸿蒙 NetworkKit 强制要求**：每次 HTTP 请求严格遵循「创建实例 → 请求 → 销毁」三步，保证资源释放。不调用 `destroy()` 会导致底层 socket 泄漏：

```typescript
const httpRequest = http.createHttp();
try {
  const response = await httpRequest.request(url, options);
  // 处理响应
} finally {
  httpRequest.destroy();  // 鸿蒙强制：必须释放，否则 socket 泄漏
}
```

### 10.2 CryptoArchitectureKit HMAC-SHA256（鸿蒙加密 Kit）

[IotAuthUtil.ets](file:///d:/SoftwareAction/features/core/src/main/ets/service/IotAuthUtil.ets) 实现 HMAC-SHA256（legacy 设备侧密码生成），使用鸿蒙 `@kit.CryptoArchitectureKit`：

```typescript
const symKeyGenerator = cryptoFramework.createSymKeyGenerator('HMAC');
const symKey = await symKeyGenerator.convertKey({ data: keyData });
const mac = cryptoFramework.createMac('SHA256');
await mac.init(symKey);
mac.update({ data: messageData });
const result = mac.doFinal();
```

code-linter.json5 中 `no-unsafe-mac` 设为 `warn`，此处 HMAC-SHA256 为有意保留。

  new CanvasRenderingContext2D(new RenderingContextSettings(true));  // 抗锯齿

## 十二、ViewModel 模式（ArkTS 纯类）

> **鸿蒙特性**：ViewModel 是纯 ArkTS 类（不使用 ArkUI 装饰器），通过 `[...vm.data]` 浅拷贝同步到 `@State`。这是 ArkTS 类型系统与 ArkUI 装饰器分离的典型实践。

### 12.1 BaseViewModel 抽象基类

[BaseViewModel.ets](file:///d:/SoftwareAction/features/core/src/main/ets/viewmodel/BaseViewModel.ets) 是纯 TS 类（**不使用 ArkTS 装饰器**，保持业务逻辑与 UI 解耦），提供统一状态管理与异步包装：

| 成员 | 说明 |
|------|------|
| `isLoading: boolean` | 加载状态 |
| `errorMsg: string` | 错误信息（空串=无错误） |
| `lastUpdateTime: string` | `YYYY-MM-DD HH:mm:ss` 格式 |
| `handleAsync<T>(fn)` | 统一 try-catch 包装器，失败返回 null（降级契约） |
| `loadData()` | 抽象方法，子类实现 |

**handleAsync 核心逻辑**：进入 `setLoading(true)` → try 执行 fn 成功后 `updateTimestamp()` → catch 区分 Error/string/其他类型构造 msg + `Logger.error` + **返回 null** → finally `setLoading(false)`。

### 12.2 四个具体 ViewModel

| ViewModel | 数据来源 | mock 降级 |
|-----------|----------|-----------|
| DashboardViewModel | IoT `smartRoom` 属性 | 默认 6 个传感器，`props === null` 保持 mock |
| DeviceViewModel | `IotService.isDeviceOnline()` | 设备列表本地 mock，仅同步在线状态 |
| GrowthViewModel | 纯本地 mock | 仅刷新时间戳 |
| AlertViewModel | 由 DashboardViewModel 派生 | 依赖上游传感器 mock |

### 12.3 DashboardViewModel 状态计算

**属性映射**（`extractSensorValue`）：用显式 `switch` 分支按 SensorType 取值，**避免动态属性访问（ArkTS 限制）**。`SOIL_TEMP` 返回 null（云平台未定义，保持 mock）。

**状态计算规则**（`calculateStatus`）：

- 在 `[min, max]` 内 → 0（正常）
- 超出 < 10% → 0（容差）
- 超出 10%~20% → 1（警告）
- 超出 ≥ 20% → 2（危险）

**控制命令乐观更新**（`refreshControl`）：先本地改状态 → 下发命令 → 失败则回滚。

### 12.4 Page 与 ViewModel 绑定（ArkUI 状态同步）

ViewModel 是普通 TS 类，Page 在 `aboutToAppear` 通过 `[...vm.data]` 浅拷贝同步到 `@State`（**ArkUI 状态同步模式**）：

```typescript
private viewModel: DashboardViewModel = new DashboardViewModel();

aboutToAppear(): void {
  this.sensors = [...this.viewModel.sensors];   // 先同步 mock 避免首帧空白
  this.controls = [...this.viewModel.controls];
  this.loadFromViewModel();                      // 异步加载云端
}
```

## 十五、编码规范与安全（ArkTS 约束）

> **鸿蒙特性**：ArkTS 是 TypeScript 超集，但禁用 `any`、动态属性访问、object literal 无接口等，这是鸿蒙类型系统的强制约束，区别于普通 TS。

### 15.1 ArkTS 编码约束（鸿蒙强制）

| 规则 | 说明 | 鸿蒙特有 |
|------|------|----------|
| 禁止 `any` | 所有变量显式类型声明，禁止 `as` 类型断言 | ✅ ArkTS 类型系统 |
| 禁止 object literal 无接口 | 必须有 declared interface/class | ✅ ArkTS 类型系统 |
| 禁止动态属性访问 | `obj[dynamicKey]` 不允许，用显式 switch/if-else | ✅ ArkTS 限制 |
| 状态拆分 | 大状态对象按刷新频率拆分 `@State` | ✅ ArkUI 性能 |
| build() 轻量 | 禁止网络请求/重计算/同步 I/O，异步 init 放 aboutToAppear | ✅ ArkUI 规范 |
| 列表性能 | ≤100 用 ForEach，>100 用 LazyForEach + @Reusable + cachedCount | ✅ ArkUI 组件 |
| 动画 | 仅合成属性（translate/scale/opacity/rotate），禁止布局属性 | ✅ ArkUI 动画 |
| 布局深度 | ≤ 5 层，合并同向冗余嵌套 | ✅ ArkUI 布局 |
| 单位 | vp 布局、fp 字体、`'100%'` 百分比、`layoutWeight()` flex | ✅ 鸿蒙单位系统 |
| null 安全 | 可选链 `?.` + 空值合并 `??` | ✅ ArkTS |
| async | 必须 try-catch | ✅ ArkTS |
| 能力调用 | 必须 `canIUse()` 守卫 | ✅ 鸿蒙分布式 |

### 15.2 文件命名规范

| 类型 | 命名 |
|------|------|
| 页面 | `XxxPage.ets` |
| 组件 | `XxxComponent.ets` |
| 工具 | `XxxUtils.ets` |
| 模型 | `XxxModel.ets` |
| ViewModel | `XxxViewModel.ets` |
| 服务 | `XxxService.ets` |
| 常量 | `XxxConstants.ets` |

### 15.3 凭证安全

- `**/IotConfig.ets`（真实凭证）：gitignored，永不提交

## 十六、技术亮点总结

本项目深度应用鸿蒙核心特性，十大技术亮点：

1. **Stage Model 应用模型**：基于鸿蒙 Stage Model 的 UIAbility 生命周期，onCreate 三步初始化（锁色模式 + IoT 服务 + 主题），onWindowStageCreate 加载入口页，全部 try-catch 包裹保证单点失败不影响启动。

2. **三层模块化架构**：HAR/HAR/HAP 严格单向依赖（鸿蒙模块类型），OHPM 包管理（替代 npm），barrel 导出，模块类型通过 harTasks/hapTasks 区分（Hvigor 构建系统）。

3. **一次开发多端部署**：五档断点（XS/SM/MD/LG/XL，鸿蒙核心理念）+ onAreaChange 实时检测 + AppStorage 全局共享 + AdaptiveUtils 工具方法 + GridRow/GridCol span 动态计算（鸿蒙响应式组件），覆盖手表到 PC 全设备形态。

4. **双模式入口**：窄屏底部 Tabs + 宽屏 SideNavBar(220vp) + Navigation(Stack)（鸿蒙路由三件套），跨模式共享 NavPathStack（AppStorage 全局状态）。

5. **ArkUI 装饰器状态管理**：@State/@Prop/@Link/@Watch/@StorageLink 五种装饰器（鸿蒙特有），状态拆分优化重渲染，@Watch 联动主题切换，条件渲染规避 Tabs 缓存失效。

6. **双主题原子替换**：PersistentStorage 持久化（鸿蒙特有）+ AppStorage 真相源 + @StorageLink 双向绑定 + ThemeManager 单例，雾透玻璃与极致黑白两套设计语言，backdropBlur 毛玻璃效果。

7. **华为云 IoT 全链路**：IAM 鉴权 + token 缓存（23h + 提前 1 分钟刷新）+ 设备影子查询 + 同步命令下发，命令名与嵌入式 mqtt.c 严格对齐，NetworkKit http 强制 destroy() 释放资源。

8. **10 个系统 Kit 集成**：Network、Crypto、MapKit、Image、PerformanceAnalysis 等深度使用（鸿蒙 @kit.* 命名空间），MapKit + Canvas 双模式降级（canIUse 能力查询，鸿蒙分布式架构典型应用）。

9. **纯 Canvas 图表体系**：柱状/折线/仪表盘/地图全自绘（ArkUI Canvas 组件 + CanvasRenderingContext2D），无第三方依赖，颜色 @Prop 支持主题切换，onReady 确保画布就绪。

10. **严格工程规范**：caseSensitiveCheck + useNormalizedOHMUrl（鸿蒙严格模式）+ CodeLinter 安全规则 + hypium 单元测试（鸿蒙测试框架）+ 凭证隔离 + ArkTS 类型系统约束（禁用 any/dynamic）。
